1 Khảo sát & Phân tích 2 tuần Khảo sát hiện trạng hệ thống cũ • Phỏng vấn stakeholders (QL trung tâm, NV tiếp nhận, KTV, thủ kho) • Phân tích quy trình AS-IS • Đánh giá hạ tầng CNTT • Xác định pain points và kỳ vọng
  • Báo cáo khảo sát hiện trạng
  • Tài liệu phân tích quy trình AS-IS
  • Danh sách yêu cầu nghiệp vụ (BRD)
  • Biên bản phỏng vấn stakeholders
2 Thiết kế hệ thống 3 tuần Thiết kế kiến trúc tổng thể (system architecture) • Thiết kế cơ sở dữ liệu (ERD) • Thiết kế UI/UX wireframe + high-fidelity mockup • Thiết kế API specification • Thiết kế quy trình nghiệp vụ TO-BE • Thiết kế bảo mật & phân quyền
  • Bản thiết kế kiến trúc hệ thống
  • ERD & Database Schema
  • UI/UX Wireframe (Figma)
  • High-fidelity Mockup (Figma)
  • API Specification (OpenAPI/Swagger)
  • Quy trình nghiệp vụ TO-BE
3 Lập tài liệu 2 tuần Biên soạn SRS (Software Requirements Specification) • Biên soạn SDD (Software Design Document) • Biên soạn tài liệu UI/UX • Biên soạn API Documentation • Lập Test Plan • Lập kế hoạch triển khai
  • Tài liệu SRS
  • Tài liệu SDD
  • Tài liệu hướng dẫn UI/UX
  • Test Plan & Test Cases
  • Kế hoạch triển khai

  • Tài liệu đã phê duyệt (final)
  • Biên bản xác nhận tài liệu
  • Change request log (nếu có)
5 Kickoff & Chuẩn bị 1 tuần Họp kickoff dự án • Setup môi trường Dev/Staging/Production • Setup CI/CD pipeline (GitHub Actions) • Setup project management (Jira/Linear) • Phân công nhân sự • Setup monitoring (Sentry)
  • Biên bản họp kickoff
  • Môi trường Dev/Staging sẵn sàng
  • CI/CD pipeline hoạt động
  • Backlog sprint 1 đã tạo

🏃 Chi Tiết Sprint Phát Triển (Agile Scrum)

Mỗi Sprint kéo dài 2 tuần, bao gồm: Sprint Planning (2h) → Daily Standup (15min/ngày) → Development → Code Review → Testing → Sprint Review (1h) → Retrospective (1h)

Sprint 1 Tuần 10-11

Foundation — Nền tảng dự án

  • Scaffold monorepo (Turborepo + 3 apps)
  • Setup PostgreSQL + Prisma ORM schema
  • LG Design System tokens (colors, typography)
  • Shared component library cơ bản
  • Setup Redis + BullMQ
  • NestJS project structure + modules
Sprint 2 Tuần 12-13

Authentication — Xác thực & Phân quyền

  • Customer OTP registration + login
  • Admin email/password login
  • JWT access + refresh token
  • RBAC 4 vai trò (Guard + Decorator)
  • Branch isolation middleware
  • Mobile + Web login screens
Sprint 3 Tuần 14-15

Customer Booking — Đặt lịch khách hàng

  • Đăng ký thiết bị LG (serial, model)
  • Kiểm tra bảo hành theo serial
  • Tạo đơn đặt lịch (full form flow)
  • Xem báo giá ước tính
  • Order state machine (backend)
  • Push notifications (FCM)
Sprint 4 Tuần 16-17

Web Admin — Quản lý đơn & Điều phối

  • Dashboard đơn hàng (list + filter + search)
  • Chi tiết đơn + timeline
  • Tạo đơn walk-in
  • Điều phối KTV (assign)
  • Quản lý khách hàng (CRUD)
  • Quản lý tài khoản nhân viên
  • Audit log
Sprint 5 Tuần 18-19

Technician App — Quy trình KTV

  • Job list + job detail (KTV screen)
  • Accept/Reject đơn + reason code
  • Status updates (en route → completed)
  • Completion form + checklist
  • Chữ ký điện tử khách hàng
  • Chụp ảnh trước/sau
  • Offline mode (cache + sync)
  • Google Maps navigation
Sprint 6 Tuần 20-21

Inventory — Quản lý kho linh kiện

  • Master parts catalog (CRUD)
  • Per-branch stock levels
  • Goods receipt (nhập kho batch)

  • Low-stock alerts
  • Inter-branch transfer workflow
  • Inventory reports
Sprint 7 Tuần 22-23

Payment — Thanh toán & Hoá đơn

  • VNPay integration (full webhook flow)
  • MoMo integration
  • Cash payment recording

⚠️ Quản Lý Rủi Ro
# Rủi ro Mức độ Xác suất Biện pháp phòng ngừa
1 Yêu cầu thay đổi liên tục (scope creep) Cao Trung bình Freeze requirements sau GĐ4. Mọi thay đổi qua Change Request process. Demo mỗi 2 sprint để confirm sớm.
2 Tích hợp VNPay/MoMo phức tạp hơn dự kiến TB Trung bình Nghiên cứu sandbox sớm từ Sprint 5. Buffer 1 tuần trong Sprint 7. Liên hệ support gateway trước khi code.
3 Data migration từ hệ thống cũ gặp lỗi Cao Trung bình Profile data quality từ GĐ1. Chạy dry-run migration 2 lần trước go-live. Script rollback sẵn sàng.
4 Thiếu nhân sự chuyên môn React Native TB Thấp Tuyển dụng sớm. Sử dụng Expo để giảm yêu cầu native experience. Pair programming giữa senior và junior.
5 Performance chậm khi nhiều chi nhánh dùng đồng thời TB Thấp Load testing từ Sprint 6. Database indexing + query optimization. Redis cache cho hot data. Read replica nếu cần.
6 App bị reject trên App Store / Google Play Cao Thấp Tuân thủ guidelines từ đầu. Submit review sớm (TestFlight/Internal Testing). Chuẩn bị tài liệu privacy policy.
